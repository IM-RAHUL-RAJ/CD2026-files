Global

Managed

Definition from PDF 01: access computing resources like servers, storage, databases and software over the internet, rather than owning and maintaining physical hardware.

Who manages what? The pizza test

Pizza analogy: homemade (on-prem: you do everything), take-and-bake (IaaS: you get the dough, you cook), delivery (PaaS: just bring the table), dine out (SaaS: just eat).

Examples: IaaS = EC2; PaaS = AWS Elastic Beanstalk; SaaS = Gmail, Zoom.

Three ways to deploy a cloud

Public cloud

Shared provider infrastructure, used by many customers over the internet.

ExampleAWS, Azure, Google Cloud. Most startups and enterprises.

Private cloud

Cloud-style infrastructure dedicated to one organization.

ExampleBanks or governments with strict data rules, often on VMware or OpenStack.

Hybrid cloud

Private and public together. Data and apps move between them.

ExampleCore banking on-prem, mobile app and analytics on AWS.

From PDF 01. Ask: which one is your college lab? (Usually private/on-prem.) Which one runs your favourite food delivery app? (Usually public cloud.)

From one OS per machine to many

Step 1: the classic stack: hardware, one OS, apps. Step 2: the hypervisor slices the hardware into virtual machines, each with its own OS. Step 3: they're fully isolated. A crash in one doesn't touch the others.

A hypervisor hands out slices of real hardware

These are the exact numbers from the virtualization PDF: an 8 GB / 100 GB host gives VM1 2 GB RAM and 20 GB disk, VM2 2 GB and 10 GB. The rest stays free for more VMs.

Type 2 on your laptop, Type 1 in the cloud

Type 2 · hosted

VirtualBox, VMware Workstation. Great for learning: “Linux VirtualBox on Windows”.

Type 1 · bare metal

VMware ESXi, Xen, KVM, AWS Nitro. No host OS in the way. Used by cloud providers and enterprise servers.

Type 2 runs as an app on top of your OS, so it's slower but convenient. Type 1 runs directly on the hardware, which is faster and more secure. AWS EC2 originally used Xen and now uses the Nitro hypervisor, which is based on KVM.

Why every company virtualizes

Cheaper

One big server replaces many half-empty ones.

Less space

Fewer racks, smaller rooms.

Less energy

Fewer machines to power and cool.

Snapshots

Save a whole machine's state in seconds.

Fast recovery

Host died? Restart the VM on another host.

From the virtualization PDF: cheap, reduces workload, space, energy, easy backup using snapshots, easy recovery.

How can one server be my server and your server at the same time?
Your EC2 instance is a virtual machine: a slice of a real server, cut by a Type 1 hypervisor.
AWS built its own hypervisor and hardware, the Nitro System, so the slices run at nearly bare-metal speed and stay isolated from every other customer.
