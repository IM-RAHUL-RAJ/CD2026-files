Five ideas behind infrastructure as code

Declarative

Say what you want. CloudFormation works out how and in what order.

Template

YAML or JSON, stored in Git, reviewed in pull requests.

Stacks

Everything from one template, managed together. StackSets: many accounts and Regions.

Managed state

AWS tracks what exists. No separate state file to lose.

Drift detection

Someone changed prod by hand? CloudFormation reports it.

CloudFormation itself is free. You pay only for what it creates.

All five points from PDF 12. Drift detection answers the "who changed prod at midnight" half of the struggle question.

CloudFormation, Terraform, CDK

CloudFormation

AWS-native. YAML/JSON. State managed by AWS. Day-one support for new AWS features is common.

Pick whenYou're all-in on AWS.

Terraform

Multi-cloud. HCL language. You manage a state file (often in S3 + a lock).

Pick whenYou use AWS plus other clouds or SaaS.

AWS CDK

Write infrastructure in TypeScript, Python or Java. Generates CloudFormation.

Pick whenYour team prefers real code: loops, functions, tests.

All three are common in Indian enterprises. Terraform is especially common in multi-cloud shops; CDK in developer-heavy teams.

Why pay all day for a 3-second job, and how do you survive 2 million clicks?
Run short jobs on Lambda so idle time costs nothing, and put a queue in front of anything that can't keep up.
The queue turns a spike into a steady line. Nobody's payment is dropped; it just waits a few seconds.
