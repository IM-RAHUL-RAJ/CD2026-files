The lab way vs the enterprise way

Lab: keys in the command

docker run -d -p 80:3000 \
  -e AWS_ACCESS_KEY_ID=AKIA... \
  -e AWS_SECRET_ACCESS_KEY=wJal... \
  node-dynamodb-demo

Fine for a 10-minute tutorial. Keys sit in shell history, process lists and screenshots.

Enterprise: a role, no keys

docker run -d -p 80:3000 \
  -e AWS_REGION=ap-south-1 \
  node-dynamodb-demo
# the SDK finds temporary credentials
# from the instance role automatically

Attach an IAM role to the EC2 instance or ECS task. Nothing to leak, nothing to rotate.

✓ Never use root after setup
✓ Permissions on groups, not people
✓ MFA + password policy
✓ Never share keys or passwords
✓ Roles for apps, SSO for people
✓ Audit with the credential report

The left command is the DynamoDB lab from PDF 10. It's a great way to learn, and a bad way to run production. The checklist is PDF 03's IAM best practices, updated: modern teams prefer roles and SSO over long-term access keys.

Why can't Rahul just get the admin password?
Because in an enterprise, nobody has a permanent admin password. People get SSO + MFA, apps get roles, and every key expires.
If Rahul's laptop is stolen tomorrow, the thief gets almost nothing. That's the whole point.
