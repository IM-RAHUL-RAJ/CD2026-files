Setting up your first AWS account

1 · Sign up

Root user email + account name. The email becomes the master key.

2 · Verify

Email code, phone, and a card for identity. Free tier covers learning.

3 · Lock root

Turn on MFA for root. Never create root access keys.

4 · Budget alert

Set an AWS Budgets alert before any lab.

5 · Daily identity

Create an admin user or IAM Identity Center login for daily work.

12digits in every account ID

Students: the most common surprise bill comes from a forgotten instance or NAT gateway. Budget alert first, lab second, delete everything third.

From the "AWS Account Setup" section of PDF 02: root user email address (used for account recovery and some administrative functions), account name, verify email. Free tier details change, so point people to aws.amazon.com/free.

Console, CLI, SDK: three doors, one API

Console

Point and click in a browser. Best for learning and exploring.

CLI

Commands and scripts. Best for repeatable tasks.

$ aws configure
$ aws s3 ls
$ aws ec2 describe-instances \
    --region ap-south-1
$ aws sts get-caller-identity

SDK

Code inside your app: Python, Java, Node, Go…

import boto3
s3 = boto3.client("s3")
for b in s3.list_buckets()["Buckets"]:
    print(b["Name"])

All three end up as the same signed HTTPS API call.

From PDF 03 (IAM): the Management Console is graphical, the CLI is command-line and scripting, the SDKs and APIs are programmatic. aws sts get-caller-identity is the "who am I?" command from the EKS PDF; run it whenever credentials are confusing.
