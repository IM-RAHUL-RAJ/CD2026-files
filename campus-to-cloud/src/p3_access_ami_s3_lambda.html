An open door, or no door at all

Left: SSH needs port 22 open. Click: the moment it's open to the internet, bots start knocking. Click: Session Manager. The agent on the server dials out to AWS; Kabir connects through AWS. Nothing needs to come in.

SSH: a lock on the server, a key in your pocket

# only you may read the key
chmod 400 chaicart.pem
# the username depends on the AMI
ssh -i chaicart.pem ec2-user@13.233.41.7  # Amazon Linux
ssh -i chaicart.pem ubuntu@13.233.41.7    # Ubuntu

AWS keeps the public key (the lock) on the server. You download the private key once. AWS never stores it.

Connection timed out

The network blocked you: SG rule, no public IP, or no route to the IGW.

Permission denied (publickey)

You reached the server. Wrong username or wrong key.

UNPROTECTED PRIVATE KEY FILE

Run chmod 400 on the key.

The most useful debugging tip of the day: timeout = network problem, permission denied = login problem.

Four ways into a server

SSH + key

Port 22 open · .pem to guard · little audit trail.

Use forLabs, quick tests.

EC2 Instance Connect

Pushes a one-time key valid for 60 seconds. Still needs port 22.

Use forConsole SSH without managing keys.

Session Manager

No ports · no keys · IAM decides · every session can be logged.

Use forProduction. The modern default.

Bastion host

A public jump server in front of private ones. One more server to patch.

Use forLegacy setups. Being replaced by SSM.

Production direction: close port 22 everywhere, use Session Manager, and log every session.

Behind the scenes

How Session Manager reaches a private server

The agent makes outbound HTTPS connections to the Systems Manager endpoints and keeps a channel open. When you start a session, IAM checks your permission and your keystrokes travel over that channel.

Private subnet with no NAT? Add interface VPC endpoints for ssm, ssmmessages and ec2messages. The instance role needs the AmazonSSMManagedInstanceCore policy.

Behind the scenes

Snapshots only save what changed

Snapshot 1 copies every used block.

Snapshot 2 copies only changed blocks.

Stored durably in S3, managed by AWS. An AMI points at snapshots like these, so deleting an old snapshot never breaks a newer one.

ThingWhat it is

The grid is a disk's blocks. Snapshot 1 copies all used blocks. Then the app changes a few; snapshot 2 copies only those (amber). Each snapshot can still restore a full disk because it references unchanged blocks from earlier ones.

Chapter 7

A warehouse that never fills

Menu photos, invoices, backups, logs. Meera wants all of it safe forever.

S3

S3 is the oldest AWS service still at the heart of almost everything, launched in March 2006.

Buckets hold objects. Keys find them.

S3 is object storage: you PUT and GET whole objects over HTTPS. It's not a disk you mount and edit in place.

The maximum object size was raised to 50 TB (per AWS's 20-years-of-S3 post, March 2026). Since December 2020 S3 has strong read-after-write consistency.

Data cools down. So should its price.

Every class keeps the same 11-nines durability design; they differ in price, retrieval time and minimum storage duration. One Zone-IA is the exception: it stores data in a single AZ.

Object, block or file?

S3

Objects over HTTPS. Unlimited. Many readers.

Use forMedia, backups, data lakes, static sites.

EBS

A block disk for one instance, in one AZ.

Use forBoot disks, databases on EC2.

EFS

A shared Linux folder (NFS). Grows by itself.

Use forMany servers sharing files.

FSx

Managed Windows, Lustre, NetApp, OpenZFS file systems.

Use forWindows shares, HPC.

Interview favourite: "Where would you store user-uploaded images?" S3. "Where does the database's data live?" EBS (or let RDS handle it).

AWS figures, March 2026.

For S3 Standard, AWS stores objects redundantly across a minimum of three AZs. Internally it uses techniques like erasure coding: the data is split into pieces plus extra parity pieces, so it can be rebuilt from a subset.

The scale numbers are from AWS's "Twenty years of Amazon S3" post, March 2026: over 500 trillion objects, over 200 million requests per second, tens of millions of hard drives. Auditor processes continuously check every byte and trigger repairs.

Three ways production apps use S3

Website + CDN

HTML, JS and images served from edge caches. No servers.

Direct upload

A link valid for minutes. Files skip your servers.

Data lake

Dump everything in S3, query it with SQL later.

Keep Block Public Access on. Most S3 leaks in the news were buckets someone opened to the world.

Block Public Access is on by default for new buckets (since April 2023). Turning it off plus a bucket policy with Principal "*" is how most S3 data leaks happened.

A chef who appears only when an order arrives

Every new menu photo needs a thumbnail. Kabir doesn't want a server sitting idle all day for that.

λFC

Serverless: there are still servers. You just never see, patch or pay for them while idle.

Zero to a thousand, and back to zero

0copies running now

No events, no copies, no bill.

Each copy handles one event at a time. Lambda adds copies as events pile up.

The squares on the left are events (an upload, an API call, a message). Lambda starts more copies of your function as events arrive and removes them when it's quiet.

Cold start, warm start

A cold start happens when there's no ready environment: Lambda downloads your code, starts an isolated microVM, starts the runtime and runs your initialisation code. Warm invocations reuse that environment.

Reduce cold starts: keep packages small, do heavy setup outside the handler, or use provisioned concurrency / SnapStart where it fits.

Firecracker is AWS's open-source virtual machine monitor, written in Rust. It gives each function the isolation of a VM with nearly the speed and density of a container. The launch post quoted boot in as little as 125 ms and about 5 MiB of memory overhead per microVM.

When Lambda, when not?

Lambda

Event-driven, ≤ 15 min, scales to zero.

Use forThumbnails, webhooks, cron jobs, glue code.

Fargate

Containers without servers. No time limit.

Use forWeb APIs, workers that run for hours.

EC2

Full control, always on, cheapest at steady load.

Use forHeavy steady traffic, GPUs, special OS.

Step Functions

A workflow that chains Lambdas, with retries and waits.

Use forOrder flows, anything longer than 15 minutes.

In production

ChaiCart's thumbnail pipeline: upload to S3 triggers a Lambda, which writes to a different prefix (never the same one, or you trigger yourself forever!) and notifies via SNS.
