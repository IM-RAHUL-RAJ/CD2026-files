Activity 2

Why can't Ananya open Rahul's app?

Ask the room which switch to flip next. The packet stops at the first broken gate.

This is the number one "my EC2 doesn't work" debugging path. Start with the default state: the packet dies at the route table. Let the audience fix one gate at a time. The last gate catches developers who bind their app to localhost.

The success message is the user-data Apache page from PDF 04.

Activity 3

Ananya's team needs Rahul's database

Rahul's database lives in VPC A. Ananya's analytics app lives in VPC B, owned by another team. Make the connection work.

Bonus question: does IAM need to change? (No. IAM controls API calls, not packets.)

The classic peering checklist: non-overlapping CIDRs, a peering connection requested and accepted, routes on both sides, and security group rules. Most people forget the return route.

For many VPCs, use Transit Gateway instead (see the earlier compare slide).

Why can't my friend open my app?
Every packet passes five gates: public IP → route to IGW → NACL → security group → app listening on 0.0.0.0.
“Timed out” means a gate blocked it. “Connection refused” means it reached the OS but nothing was listening. Now you can debug any EC2 in two minutes.
