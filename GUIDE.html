Deploy your project, step by step

From nothing to your trading project running on an AWS machine in Docker, and then with its database on RDS. Do the steps in order. Every command is here, and so is every file, ready to copy.

  1. Write the config file
  2. Create the EC2 machine
  3. Connect to it and install the tools
  4. Put your project on the machine
  5. Copy the deployment files, one by one
  6. Apply the config and type the passwords
  7. Run it with docker-compose
  8. Check it works, and check the addresses
  9. Create the RDS database
  10. Replace the Postgres container with RDS
  11. The VPCs: who can reach the database
  12. What comes next, and the rest of the files
Three rules.
  1. You do not write Dockerfiles or a docker-compose file. You copy ours, unchanged.
  2. You edit exactly one file: deploy/config/application.yaml. Every folder, port and address of your project lives there.
  3. Passwords and keys never go in that file. They go in deploy/.env, which is never committed.

Step 1Write the config file

Where: your laptop, with your project open. Nothing is installed.

Our Dockerfiles and compose file know nothing about your project. They do not know your folders, your ports, your database name, or what your code calls its settings. The config file tells them. It is a list of answers to questions about your project.

This step shows how I wrote that file for one real project, team5 (Neueda-Learning/chennai-capstone-SE6-team5), question by question: what I ran, what came back, and what I typed. Do the same for yours. At the end you have a finished file, which you paste on the machine in step 5.

Question 3. Which port does each one listen on?

A Java (Spring) service says so in application.properties. A Node service says so where it reads PORT.

grep -rn 'server.port' --include='application*.properties' --include='application*.yml' . | grep -v /target/
grep -rn 'process.env.PORT' Services/auth-service/src
What team5 printed
Services/executor-service/src/main/resources/application.properties:2:server.port=${SERVER_PORT:8082}
Services/order-service/src/main/resources/application.properties:2:server.port=${SERVER_PORT:8081}
Services/auth-service/src/config/runtime-config.ts:74:  const rawPort = process.env.PORT?.trim() || '3000';

So: order 8081, executor 8082, auth 3000. The number after the colon or the || is the port. For the frontend, use 4200; it is the port people will type in the browser.

Question 4. Which address shows that each one is alive?

Docker calls this address every few seconds to know whether the container is healthy. It must answer without a login.

  • Java: /actuator/health, if the project has the actuator. Check: grep -l actuator Services/*/pom.xml must list the service.
  • Node and the frontend: / usually works. If your auth service answers 404 on /, use a path that answers 200, such as its docs page.

Question 6. Which settings does the code read?

This is the block that takes the most care, and it is the reason one set of files fits every project. One team's code reads DB_HOST, another's reads POSTGRES_HOST. Our files know neither name. Whatever you list under env is handed to every container, under exactly the names you write.

First, list every name the code reads. Java reads them as ${NAME:default}, Node as process.env.NAME.

Then put each name in one of four piles:

The setting isWhat to doteam5 example
An address, host or port of something we runPut it under env with a placeholder from the table below. Never type an IP here.POSTGRES_HOST: "{db_host}"
A password, key or tokenPut only its name under secrets.JWT_SECRET

A placeholder is a word in curly brackets. apply.py swaps it for the right value, so the same file works on your laptop, in Docker and later on Kubernetes.

Where: AWS console, in a browser

  2. Search for EC2, open it, and click Launch instance.
  3. Fill in the form as below. Leave everything else as it is.

  2. Click the instance and write down its Public IPv4 address. You need it in steps 6 and 8.

Open the ports

Click the instance, the Security tab, the security group's name, then Edit inbound rules. Add one rule per port. For each: Type Custom TCP, the port, Source My IP.

PortWhat answers on it
4200The page (your frontend's port)
3000The auth service (your auth port)

The public IP changes every time the machine is stopped and started. If that happens, repeat the short "change the address" block in step 8. Your own IP can change too; if the page stops loading one morning, edit the rules and choose My IP again.

Step 4Put your project on the machine

Where: the terminal on the machine

Replace the address with your project's. Use the https:// address from the green Code button on GitHub.

cd ~

cd <your-project>
ls

If the repository is private, git asks for a username and a password. The password is not your GitHub password; it is a token:

  1. On GitHub: your picture, Settings, Developer settings, Personal access tokens, Tokens (classic), Generate new token (classic). Tick repo. Copy the token.
  2. If your organisation uses single sign-on, click Configure SSO next to the token and authorise the organisation. Without this the clone fails with 403.

# produces one runnable jar. Explained in GUIDE.html, step 5.

# Stage 1: compile
ARG RUNTIME_VERSION=21
FROM maven:3.9.9-eclipse-temurin-${RUNTIME_VERSION} AS builder
WORKDIR /app

COPY pom.xml .
RUN mvn -B dependency:go-offline -q

COPY src ./src
RUN mvn -B package -DskipTests -q

# Stage 2: run
ARG RUNTIME_VERSION=21
FROM eclipse-temurin:${RUNTIME_VERSION}-jre-alpine AS runtime
WORKDIR /app

RUN addgroup -S app && adduser -S app -G app
COPY --from=builder --chown=app:app /app/target/*.jar /app/app.jar

ARG APP_PORT=8080
ENV APP_PORT=${APP_PORT} SERVER_PORT=${APP_PORT}
EXPOSE ${APP_PORT}
ENV JAVA_OPTS=""

USER app

ARG HEALTH_PATH=/actuator/health
ENV HEALTH_PATH=${HEALTH_PATH}
HEALTHCHECK --interval=15s --timeout=5s --start-period=40s --retries=5 \
    CMD [ -z "$HEALTH_PATH" ] || wget -qO- "http://localhost:${SERVER_PORT}${HEALTH_PATH}" >/dev/null || exit 1

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar /app/app.jar"]

An Angular page is built into fixed files, so it cannot read a setting later the way a server can. Our image writes the two API addresses into a small file, app-config.js, each time the container starts. Your page has to load that file and use what is in it.

const runtime = (globalThis as any).__APP_CONFIG__ ?? {};
export const authBaseUrl  = runtime.authBaseUrl  ?? 'http://localhost:3000';

load_sql() {
  for path in $SQL_PATHS; do
    if [ -d "/project/$path" ]; then
      files=$(ls -1 "/project/$path"/*.sql 2>/dev/null | sort)
    elif [ -f "/project/$path" ]; then
      files="/project/$path"
    else
      echo "SQL path not found in the project: $path" >&2

    for f in $files; do
      echo "== $f"
      psql -v ON_ERROR_STOP=1 -q -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f "$f" || return 1
    done
  done
  echo "== SQL loaded"

def listen_port(service):
    """The port inside the container. nginx serves an Angular build on 80."""
    return 80 if service["type"] == "angular" else service["port"]


def placeholders(cfg, phase):
    """The values an `env` entry can refer to as {name}, for this phase."""
    svc, db, kafka, mail, pub = cfg["services"], cfg["database"], cfg["kafka"], cfg["mail"], cfg["public"]
    scheme, host = pub.get("scheme", "http"), str(pub["host"])
    if phase == "eks":
        # One load balancer serves the page and both APIs, so the browser
        # needs no API address, and services find each other by name.
        base = f"http://{LB}"
        out = {"frontend_url": base, "auth_url": "", "order_url": "", "cors_origins": base,
               "cookie_secure": "false"}
        internal = {role: f"http://{NAMES[role]}:{svc[role]['port']}" for role in ("auth", "order")}
    else:
        base = f"{scheme}://{host}"
        origins = [f"{base}:{svc['frontend']['port']}"]
        if host in LOCAL_HOSTS:
            origins += [f"{scheme}://{h}:{svc['frontend']['port']}" for h in LOCAL_HOSTS if h != host]
        out = {"frontend_url": origins[0],
               "auth_url": f"{base}:{svc['auth']['port']}",
               "order_url": f"{base}:{svc['order']['port']}",
               "cors_origins": ",".join(origins),
               # Browsers drop Secure cookies over plain http, except on localhost.
               "cookie_secure": "true" if scheme == "https" or host in LOCAL_HOSTS else "false"}
        if phase == "docker":
            internal = {role: f"http://{NAMES[role]}:{svc[role]['port']}" for role in ("auth", "order")}
        else:
            internal = {role: f"http://localhost:{svc[role]['port']}" for role in ("auth", "order")}
    mailpit = mail.get("mailpit", False)
    if phase == "local":
        # Started by hand, the services reach Postgres, Kafka and Mailpit
        # through the ports docker-compose publishes on the machine.
        out.update({"db_host": "localhost" if db["host"] == "postgres" else db["host"],
                    "kafka": "localhost:9092",
                    "mail_host": "localhost" if mailpit else mail["host"]})
    else:
        out.update({"db_host": db["host"], "kafka": f"{kafka['host']}:{kafka['port']}",
                    "mail_host": "mailpit" if mailpit else mail["host"]})
    out.update({"db_port": db["port"], "db_name": db["name"], "db_user": db["user"],
                # RDS accepts only encrypted connections; the container does not offer them.
                "db_sslmode": "disable" if db["host"] == "postgres" else "no-verify",
                "mail_port": 1025 if mailpit else mail["port"],
                "auth_internal": internal["auth"], "order_internal": internal["order"]})
    return out


def app_env(cfg, phase):
    """The project's own settings, with the placeholders filled in."""
    values = placeholders(cfg, phase)
    out = {}
    for key, value in (cfg.get("env") or {}).items():
        try:
            out[key] = str(value).format(**values)
        except KeyError as err:
            sys.exit(f"env.{key} uses an unknown placeholder {{{err.args[0]}}}; "
                     f"known: {', '.join(sorted(values))}")
    clash = sorted(set(out) & set(cfg.get("secrets") or []))
    if clash:
        sys.exit(f"listed under both env and secrets: {', '.join(clash)}")
    return out

        "IMAGE_PREFIX": aws["image_prefix"],

def env_line(key, value):
    value = str(value)
    # Quoted when it holds a space, so both docker-compose and bash read it whole.
    return f'{key}="{value}"' if " " in value else f"{key}={value}"


def build_env(cfg):
    lines = ["# Folders, ports and names for the scripts in deploy/scripts.",
             "# Written by config/apply.py from application.yaml. Do not edit.",
             "# No secrets: this file is committed, so the pipeline can read it."]
    lines += [env_line(k, v) for k, v in build_settings(cfg).items()
              # These two are different on every machine.
              if k not in ("PROJECT_DIR", "DEPLOY_DIR")]
    return "\n".join(lines) + "\n"


def secret_values(path, names):
    """What has already been typed into .env for each secret."""
    found = dict.fromkeys(names, "")
    if path.exists():
        for line in path.read_text().splitlines():
            key, sep, value = line.partition("=")
            if sep and key.strip() in found:
                found[key.strip()] = value
    return found


def dot_env(cfg, phase):
    path = DEPLOY / ".env"
    values = placeholders(cfg, phase)
    lines = [SECRETS_HEAD]
    lines += [f"{k}={v}" for k, v in secret_values(path, cfg.get("secrets") or []).items()]
    lines += ["", MANAGED_HEAD, f"# phase: {phase}"]
    lines += [env_line(k, v) for k, v in build_settings(cfg).items()]
    # Optional containers: Postgres unless the database is elsewhere (RDS), Mailpit if asked for.
    profiles = [name for name, wanted in (("localdb", cfg["database"]["host"] == "postgres"),
                                          ("mail", cfg["mail"].get("mailpit"))) if wanted]
    lines += [env_line("COMPOSE_PROFILES", ",".join(profiles)),
              env_line("AUTH_URL", values["auth_url"]),
              env_line("BACKEND_URL", values["order_url"]),
              "", "# The project's own settings (the `env` section)."]
    lines += [env_line(k, v) for k, v in app_env(cfg, phase).items()]
    return "\n".join(lines) + "\n"


def render(text, tokens):
    for key, value in tokens.items():
        text = text.replace(f"@@{key}@@", str(value))
    if "@@" in text:
        sys.exit("a template token was not filled in: " + text[text.index("@@"):][:40])
    return text


def k8s_files(cfg):
    """File name -> content of everything in deploy/k8s for this configuration."""
    aws, svc, mail = cfg["aws"], cfg["services"], cfg["mail"]
    templates = DEPLOY / "k8s-templates"
    kafka = f"{cfg['kafka']['host']}:{cfg['kafka']['port']}"
    common = {"NS": aws["namespace"], "KAFKA": kafka}
    files = {}
    for name in ("namespace.yaml", "storageclass.yaml", "kafka.yaml"):
        files[name] = render((templates / name).read_text(), common)
    if mail.get("mailpit"):
        files["mailpit.yaml"] = render((templates / "mailpit.yaml").read_text(), common)

    data = app_env(cfg, "eks")
    files["configmap.yaml"] = render((templates / "configmap.yaml").read_text(), {
        **common,
        # Every ConfigMap value must be a string, so all of them are quoted.
        "DATA": "\n".join(f"  {k}: {json.dumps(str(v))}" for k, v in data.items()) or "  {}",
    })

    app = (templates / "app.yaml").read_text()
    for role, name in NAMES.items():
        service = svc[role]
        cpu, memory, cpu_limit, memory_limit = RESOURCES[service["type"]]
        files[f"{name}.yaml"] = render(app, {
            **common, "NAME": name, "IMAGE": f"{aws['image_prefix']}-{name}",
            "PORT": service["port"], "LISTEN": listen_port(service),
            "HEALTH": service.get("health", "/"),
            "CPU": cpu, "MEMORY": memory, "CPU_LIMIT": cpu_limit, "MEMORY_LIMIT": memory_limit,
            # The two services that use Kafka wait until its topics exist.
            "INIT": render(WAIT_FOR_KAFKA, common) if role in ("order", "executor") else "",
        })

    rules = []
    for role in ("auth", "order", "executor"):
        for route in svc[role].get("routes") or []:
            rules.append((route, NAMES[role], svc[role]["port"]))
    rules.append(("/", "frontend", svc["frontend"]["port"]))
    paths = "".join(
        f"          - path: {route}\n            pathType: Prefix\n            backend:\n"
        f"              service:\n                name: {name}\n                port:\n"
        f"                  number: {port}\n" for route, name, port in rules)
    files["ingress.yaml"] = render((templates / "ingress.yaml").read_text(), {
        **common, "PATHS": paths.rstrip("\n"),
        "ROUTES": "\n".join(f"#   {route:<14} -> {name}:{port}" for route, name, port in rules),
    })
    files["kustomization.yaml"] = (
        "# The list `kubectl apply -k deploy/k8s` applies. Written by config/apply.py.\n"
        "apiVersion: kustomize.config.k8s.io/v1beta1\nkind: Kustomization\nresources:\n"
        + "".join(f"  - {name}\n" for name in files))
    return files


def main():
    args = [a for a in sys.argv[1:] if a != "--check"]
    check = "--check" in sys.argv[1:]
    cfg = yaml.safe_load((DEPLOY / "config" / "application.yaml").read_text())
    phase = args[0] if args else cfg["phase"]
    if phase not in PHASES:
        sys.exit(f"unknown phase '{phase}'; choose one of: {', '.join(PHASES)}")

    targets = {DEPLOY / "build.env": build_env(cfg)}
    if phase == "eks":
        targets.update({DEPLOY / "k8s" / name: text for name, text in k8s_files(cfg).items()})
    else:
        targets[DEPLOY / ".env"] = dot_env(cfg, phase)
    stale = [p for p, text in targets.items() if not p.exists() or p.read_text() != text]
    k8s = DEPLOY / "k8s"
    extra = [p for p in k8s.glob("*.yaml") if p not in targets] if phase == "eks" and k8s.exists() else []

    names = ", ".join(str(p.relative_to(DEPLOY)) for p in stale + extra)
    if check:
        if stale or extra:
            sys.exit(f"out of date for phase {phase}: {names}\nrun: python3 deploy/config/apply.py {phase}")

Step 11The VPCs: who can reach the database

A VPC is a private network inside AWS. Two rules decide whether something can reach your database:

  1. The network. Machines in the same VPC can talk on private addresses. Machines in different VPCs cannot, until the two VPCs are joined.
  2. The firewall. The database's security group must also list the caller. Being on the network is not enough.

11.1 Find which VPC each one is in

Where: AWS console
  • EC2, Instances, your instance, Networking tab: VPC ID.
  • RDS, your database, Connectivity & security tab: VPC.
What you seeWhat to do
The same VPC ID on bothNothing more. The rule from step 9 was all that was needed, and step 10 already works. This is the normal case.
Two different VPC IDsJoin them with 11.2.

You will meet the second case later even if you are in the first one now: an EKS cluster is created in a VPC of its own, so its pods cannot reach the database until the cluster's VPC is joined to the database's VPC in exactly this way.

11.2 Join two VPCs (VPC peering)

Where: the terminal on the machine

A peering connection is a private link between two VPCs. It needs three things: the link, a route on each side that says "the other network is through the link", and a firewall rule on the database for the other network. Fill in the first four lines with your own IDs.

REGION=ap-south-1
DB_VPC=vpc-xxxxxxxx        # the VPC the database is in
OTHER_VPC=vpc-yyyyyyyy     # the VPC that must reach it (the machine's, or the cluster's)
DB_SG=sg-zzzzzzzz          # the database's security group

DB_CIDR=$(aws ec2 describe-vpcs --vpc-ids $DB_VPC --region $REGION --query 'Vpcs[0].CidrBlock' --output text)
OTHER_CIDR=$(aws ec2 describe-vpcs --vpc-ids $OTHER_VPC --region $REGION --query 'Vpcs[0].CidrBlock' --output text)
echo "database $DB_CIDR   other $OTHER_CIDR"
Example
database 172.31.0.0/16   other 192.168.0.0/16

The two ranges must be different. If they overlap, peering cannot work and one side has to be recreated in another range.

# 1. the link
PCX=$(aws ec2 create-vpc-peering-connection --vpc-id $OTHER_VPC --peer-vpc-id $DB_VPC --region $REGION --query 'VpcPeeringConnection.VpcPeeringConnectionId' --output text)
aws ec2 accept-vpc-peering-connection --vpc-peering-connection-id $PCX --region $REGION --query 'VpcPeeringConnection.Status.Code' --output text

# 2. routes in both directions
for rt in $(aws ec2 describe-route-tables --region $REGION --filters Name=vpc-id,Values=$OTHER_VPC --query 'RouteTables[].RouteTableId' --output text); do
  aws ec2 create-route --region $REGION --route-table-id $rt --destination-cidr-block $DB_CIDR --vpc-peering-connection-id $PCX
done
for rt in $(aws ec2 describe-route-tables --region $REGION --filters Name=vpc-id,Values=$DB_VPC --query 'RouteTables[].RouteTableId' --output text); do
  aws ec2 create-route --region $REGION --route-table-id $rt --destination-cidr-block $OTHER_CIDR --vpc-peering-connection-id $PCX
done

# 3. the database's firewall accepts the other network
aws ec2 authorize-security-group-ingress --group-id $DB_SG --protocol tcp --port 5432 --cidr $OTHER_CIDR --region $REGION

#   deploy/scripts/bootstrap.sh

    aws ecr create-repository --region "$AWS_REGION" --repository-name "$repo" >/dev/null

#!/usr/bin/env bash
# Roll the cluster to one image tag: deploy/k8s with the four images taken
# from ECR at <tag>, and the load balancer's address written into the
# settings that need it.
#
#   deploy/scripts/deploy.sh <tag>
#   RENDER_ONLY=1 deploy/scripts/deploy.sh <tag>     print what would be applied

[ -f "$DEPLOY/k8s/kustomization.yaml" ] || { echo "deploy/k8s is missing. Run: python3 deploy/config/apply.py eks" >&2; exit 1; }

lb_host() {
  kubectl -n "$NS" get ingress app -o jsonpath='{.status.loadBalancer.ingress[0].hostname}' 2>/dev/null || true
}

# Builds build/ from deploy/k8s: the address filled in, the images pinned.
render() {  # load balancer host, or "" when it does not exist yet
  rm -rf "$DEPLOY/build"; mkdir -p "$DEPLOY/build"
  cp -r "$DEPLOY/k8s" "$DEPLOY/build/base"
  [ -n "$1" ] && sed -i "s|LOAD_BALANCER_ADDRESS|$1|g" "$DEPLOY/build/base/configmap.yaml"

    echo "apiVersion: kustomize.config.k8s.io/v1beta1"
    echo "kind: Kustomization"
    echo "resources:"
    echo "  - base"
    echo "images:"
    for role in "${ROLES[@]}"; do
      echo "  - name: ${IMAGE_PREFIX}-$(name_of "$role")"
      echo "    newName: ${REGISTRY}/${IMAGE_PREFIX}-$(name_of "$role")"
      echo "    newTag: \"${TAG}\""
    done
  } > "$DEPLOY/build/kustomization.yaml"
}

wait_for_rollout() {
  for role in "${ROLES[@]}"; do
    kubectl -n "$NS" rollout status "deployment/$(name_of "$role")" --timeout=10m
  done
}

HOST="${INGRESS_HOST-$(lb_host)}"
render "$HOST"
[ "${RENDER_ONLY:-}" = 1 ] && { kubectl kustomize "$DEPLOY/build"; exit 0; }

kubectl apply -k "$DEPLOY/build"

# written. Wait for its address, write it in, and restart the pods so they
# read it (a pod reads its settings only at start).
if [ -z "$HOST" ] && grep -q LOAD_BALANCER_ADDRESS "$DEPLOY/k8s/configmap.yaml"; then

fi

echo

#!/usr/bin/env bash
# Prove the deployed application answers through the load balancer. The
# checks are the `smoke` list in config/application.yaml: a path and the
# status it must return. A path that needs a login should expect 401, which
# proves both the route and the login check.
set -euo pipefail
. "$(dirname "$0")/pipeline-env.sh"
HOST="$(kubectl -n "$NS" get ingress app -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')"
[ -n "$HOST" ] || { echo "Ingress has no address" >&2; exit 1; }
BASE="http://$HOST"

check() {  # path, expected status
  local code=""
  for _ in $(seq 1 30); do
    code="$(curl -s -o /dev/null -m 10 -w '%{http_code}' "$BASE$1" || true)"
    [ "$code" = "$2" ] && { echo "ok    $1 -> $code"; return; }
    sleep 10
  done
  echo "FAIL  $1 -> $code (wanted $2)" >&2
  return 1
}

for entry in ${SMOKE:-/=200}; do
  check "${entry%%=*}" "${entry##*=}"
done
echo "Smoke test passed: $BASE"
Jenkinsfile
// Test, build and deploy the application to the EKS cluster.
//
// Runs on the Jenkins machine itself, which already has Docker, kubectl and
// an AWS role that can push to ECR and manage the cluster. No keys are
// stored in Jenkins.
//
// In the Jenkins job, set Script Path to deploy/Jenkinsfile.
// What is built, where it goes and what is tested all come from
// deploy/build.env, which config/apply.py writes from config/application.yaml.
// One-time cluster preparation is deploy/scripts/bootstrap.sh, not this pipeline.
pipeline {
  agent any

  options {
    timestamps()
    disableConcurrentBuilds()
    timeout(time: 45, unit: 'MINUTES')
    buildDiscarder(logRotator(numToKeepStr: '15'))
  }

  // "Build with Parameters" lets a build pick its branch. The job itself
  // always tracks */main (a parameter there stops the webhook check from
  // seeing new commits); the "Select branch" stage switches the workspace
  // when another branch is asked for. Webhook builds use the default.
  parameters {
    string(name: 'BRANCH', defaultValue: 'main', description: 'Branch to build and deploy')
  }

  // GitHub calls http://<jenkins>:8080/github-webhook/ on every push, which
  // starts a build within seconds. The slow poll is only a safety net for a
  // missed call, for example while the machine was stopped.
  triggers {
    githubPush()
    pollSCM('H */2 * * *')
  }

  stages {
    stage('Select branch') {
      when { expression { params.BRANCH && params.BRANCH != 'main' } }
      steps {
        sh '''
          git fetch --no-tags origin "+refs/heads/${BRANCH}:refs/remotes/origin/${BRANCH}"
          git checkout -f "origin/${BRANCH}"
        '''
      }
    }

    // Every service with `test: true`, each in a throwaway container.
    stage('Test') {
      steps { sh './deploy/scripts/test.sh' }
    }

    stage('Build and push images') {
      // Images are tagged with the commit they were built from.
      steps { sh './deploy/scripts/build-push.sh "$(git rev-parse --short=12 HEAD)"' }
    }

    stage('Deploy to EKS') {
      steps { sh './deploy/scripts/deploy.sh "$(git rev-parse --short=12 HEAD)"' }
    }

    stage('Smoke test') {
      steps { sh './deploy/scripts/smoke-test.sh' }
    }
  }

  post {
    success { echo 'Deployed and smoke-tested.' }
    failure { echo 'Failed. The cluster keeps running the last version that rolled out.' }
    // Test containers and build leftovers, whatever the outcome.
    always  { sh 'docker image prune -f >/dev/null || true' }
  }
}
